# v1.2.0

First release of the mock credit analysis application and its complete delivery pipeline. Customers, users, Open Finance responses and credit histories are synthetic fixtures stored in the codebase.

## Credit analysis API

- Node.js 22, Express 5 and strict TypeScript, organized around domain modules, application use cases and infrastructure adapters.
- JWT authentication with analyst and viewer roles, mock user credentials and a private demo access key required at login.
- Five customer scenarios covering approval, manual review, credit restrictions, insufficient payment capacity and missing Open Finance consent.
- Credit decisions based on score, repayment history and a 30% income commitment limit, with decimal-based installment calculations and explicit decision reasons.
- Idempotent simulation requests, user-scoped application history, pagination, filters and bounded in-memory storage with expiration.
- Swagger documentation, an OpenAPI contract, health and readiness endpoints, application version reporting, structured logs and Prometheus-compatible metrics.

## Web interface

- Login with demo profile selection and an explicit access key field. Production access keys are supplied by the presenter and are not embedded in the page.
- Customer profiles with mocked Open Finance and credit history data, credit simulations with decision explanations, application history and a customer portfolio.
- Light and dark themes, responsive layouts, keyboard navigation and separate JavaScript/CSS assets under a content security policy that disallows inline scripts.

## Delivery pipeline

- GitHub Actions validates dependencies, lint, types, tests, coverage, the production build, workflow definitions and Compose manifests.
- Production containers run on port 3016 as a non-root user with a read-only filesystem and without npm or npx in the runtime image.
- Stable Git tags drive Docker Hub image publication, application-version checks, authenticated smoke tests and vulnerability scanning, with build provenance and an SBOM.
- The Docker version tag is bound to a verified digest. Retries reuse the matching image and reject conflicting version ownership.
- GitHub-hosted runners join Tailscale and transfer a checksummed release bundle to the VPS. The VPS pulls the image by digest and routes traffic through Traefik and Cloudflare Tunnel.
- Deployment verifies internal readiness, authentication and the public route. Failed application activation triggers an attempt to restore a retained release; manual rollback is available.
- After successful deployment, GitHub Release notes record the exact commit and Docker digest. The latest markers are promoted without replacing a newer version.

## Configuration and limitations

- Production requires the documented GitHub variables and secrets, a private VPS runtime environment file, Docker Hub access and Tailscale/Traefik/Cloudflare configuration.
- Login requires the same private `DEMO_ACCESS_KEY` configured on the VPS. Production keys must contain 32 to 256 characters, at least 10 distinct characters, and must not start with `local-`.
- There is no database or real financial integration. Simulations and idempotency records expire and are lost when the application restarts, deploys or rolls back.
- This is an educational demonstration; credit decisions use fictitious data and rates.
